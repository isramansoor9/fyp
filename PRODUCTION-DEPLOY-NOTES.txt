B) BACKEND (Render): CORS — required for browser calls from Vercel
-----------------------------------------------------------------
**Do not** use `resources={r"/api/*": ...}` with Flask-CORS: in Python regex `*` repeats `/`, so paths like `/api/login` do not match and preflight OPTIONS returns **no Access-Control-Allow-Origin** (“failed to fetch”).

Current **backend/app.py** should use something like:

  - Parse **CORS_ORIGIN** as comma-separated list; strip trailing slashes per origin.
  - **CORS(app, origins=cors_origins, supports_credentials=False, allow_headers=[...], methods=[...])** globally (not tied to the broken `/api/*` resource pattern).
  - Log on boot: `[CORS] Allowed origins (...)` so Render logs confirm parsing.

**Render environment variable example:**

  CORS_ORIGIN=https://teachus-pk.vercel.app,http://localhost:3000

Redeploy backend after changing.

D) BACKEND: Urdu lesson content when user prefers Urdu
------------------------------------------------------
Implemented in **backend/app.py**, **backend/gemini_prompts.py**, **backend/gemini_service.py**:

  - `_wanted_content_language(user)` → `"ur"` if `preferredLanguage == "urdu"`, else `"en"`.
  - **user_subtopics** documents store **contentLanguage** (`"ur"` | `"en"`).
  - `/api/personalize/content` cache hit only if stored `contentLanguage` matches profile.
  - `GET /api/subtopic/...` returns empty content + `contentGenerated: false` when stored language ≠ profile (forces regeneration on client).
  - `POST /api/user/subtopic/status` sets **contentLanguage** when saving new `content`.
  - Gemini personalization receives **output_language**; prompts require full lesson in Urdu (Arabic script) when `"ur"`.
  - `_local_personalize_content` and `_append_reference_resource_section` take **output_language** for Urdu headings / resource blurb when Gemini is unavailable.

Requires **GEMINI_API_KEY** on the server for real Urdu generation (fallback is partial).
